# План рефакторинга проекта

## Текущие проблемы
1. Дублирование кода между `main.py` и `bot_lika.py` (~3400 строк в каждом)
2. Монолитные файлы - вся логика в одном месте
3. Нет разделения на слои (handlers, services, database)
4. Хардкод конфигурации в коде

## Предлагаемая структура

```
src/
├── main.py                 # Точка входа (минимальный код)
├── bot_lika.py             # Точка входа для NSFW бота
│
├── handlers/               # Обработчики Telegram событий
│   ├── __init__.py
│   ├── commands.py         # /start, /reset, /mode и т.д.
│   ├── messages.py         # Обработка текстовых сообщений
│   ├── callbacks.py        # Inline кнопки
│   └── images.py           # Генерация изображений
│
├── services/               # Бизнес-логика
│   ├── __init__.py
│   ├── llm_service.py      # Работа с LLM (OpenRouter)
│   ├── image_service.py    # Генерация изображений (все провайдеры)
│   ├── tts_service.py      # Text-to-Speech
│   ├── persona_service.py  # Управление персонажами
│   └── relationship_service.py  # Состояния отношений (для Лики)
│
├── database/               # Работа с БД
│   ├── __init__.py
│   ├── models.py           # Модели данных
│   ├── repositories.py     # CRUD операции
│   └── migrations.py      # Миграции схемы БД
│
├── config/                 # Конфигурация (уже есть)
│   └── modes.py
│
├── prompts/                # Промпты (уже есть)
│   └── ...
│
└── utils/                  # Утилиты
    ├── __init__.py
    ├── text_utils.py       # chunk_text, форматирование
    └── validators.py      # Валидация входных данных
```

## Этапы рефакторинга

### Этап 1: Выделение сервисов (1-2 дня)
- [ ] Создать `services/llm_service.py` - вынести всю логику работы с OpenRouter
- [ ] Создать `services/image_service.py` - вынести генерацию изображений
- [ ] Создать `services/tts_service.py` - вынести TTS логику
- [ ] Создать `services/persona_service.py` - управление персонажами

### Этап 2: Выделение database слоя (1 день)
- [ ] Создать `database/repositories.py` - вынести все функции работы с БД
- [ ] Создать `database/models.py` - dataclasses для данных
- [ ] Объединить `init_db()` в один модуль

### Этап 3: Разделение handlers (1-2 дня)
- [ ] Создать `handlers/commands.py` - все команды
- [ ] Создать `handlers/messages.py` - обработка сообщений
- [ ] Создать `handlers/callbacks.py` - inline кнопки
- [ ] Создать `handlers/images.py` - генерация изображений

### Этап 4: Убрать дублирование (1 день)
- [ ] Создать базовый класс `BaseBot` с общей логикой
- [ ] `main.py` и `bot_lika.py` наследуются от `BaseBot`
- [ ] Переопределяют только специфичную логику (relationship для Лики)

### Этап 5: Конфигурация (0.5 дня)
- [ ] Вынести все константы в `config/settings.py`
- [ ] Использовать pydantic для валидации конфигурации

## Преимущества новой структуры

1. **Модульность**: Каждый модуль отвечает за свою область
2. **Тестируемость**: Легко писать unit-тесты для каждого сервиса
3. **Переиспользование**: Общий код в BaseBot
4. **Читаемость**: Легче найти нужную функциональность
5. **Масштабируемость**: Легко добавлять новые фичи

## Оценка времени

- Полный рефакторинг: 5-7 дней
- Поэтапный (без остановки работы): 2-3 недели
